# 银龄守护 · 医护工作台

面向「自由赛道 · 智慧医疗」的交互原型。使用 React、TypeScript、Vite 和 ECharts，实现患者档案、风险复核与连续随访流程。

**无需数据库、后端或 Python 环境。** 全部患者、检验数值、评分、分组和解释均为人工构造的演示内容，没有接入真实医院数据或模型结果。本工程不调用上层 Python 分析程序，也没有更改其逻辑。

## 启动

建议使用 Node.js 22 或 24。在本目录执行：

```bash
npm ci
npm run dev
```

开发服务器的地址与端口由终端输出。需要指定端口时：

```bash
npm run dev -- --port 4173
```

生成、检查生产版本：

```bash
npm run build
npm run preview -- --port 4174
```

构建结果在 `dist/`，可部署到普通静态文件服务器。使用 HashRouter 和相对资源路径，刷新患者深链接无需服务器重写规则。请通过 HTTP 服务访问，不要双击 HTML 使用 `file://` 打开，否则 JSON 请求无法正常工作。

## 页面与功能

| 页面     | 路由               | 功能                                                                                   |
| -------- | ------------------ | -------------------------------------------------------------------------------------- |
| 工作台   | `/#/`              | 数据驱动的统计、重点患者、今日待办、关注分布、随访计划                                 |
| 患者目录 | `/#/patients`      | 姓名/编号/疾病搜索，疾病/关注等级/复核状态筛选，排序                                   |
| 患者详情 | `/#/patients/P001` | 四项检验切换、参考范围、数值表、模拟评分、信息缺口、诊疗时间线及随访记录               |
| 风险复核 | `/#/reviews`       | 待复核队列、示意依据、人工结论与意见、可选创建随访任务                                 |
| 随访任务 | `/#/followups`     | 今日/逾期/完成筛选，负责人筛选，创建任务、开始处理、记录联系、安排下一次日期、完成任务 |

桌面侧栏在手机端收起为菜单，宽表格在自身容器内横向滚动。支持键盘聚焦、弹窗 Escape 关闭和减少动画的系统偏好。

## 三分钟演示路径

1. 从工作台进入「林女士 P001」档案，切换血红蛋白与肌酐，展开数值表。
2. 点击「查看依据与复核」，查看模拟解释和缺失信息，记录一条人工复核意见。
3. 在该患者档案中「新建随访」，填写任务名称、计划日期、负责人及关注事项。
4. 进入随访任务中心，搜索刚创建的任务。先「开始处理」，再「填写记录」。
5. 选择「未接通」时不能结束任务，可安排下一次日期；选择「已联系」并勾选完成后，任务进入已完成。
6. 回到患者档案，在「随访记录」与「诊疗与处理时间线」查看反馈。刷新页面，记录仍保留。
7. 顶部「导出记录」保存交互记录；「重置演示」确认后恢复初始状态。

不适合直接继承旧报告中的性能数字。本版没有展示未经重新验证的 AUC、准确率或真实临床效果。模拟评分采用 0–100 展示，并明确标为非事件概率；影响因素是示意数据，未实时计算 SHAP。

## 本地数据和保存方式

```text
public/demo/dataset.json   12 位虚拟患者、初始评估、初始任务
src/types.ts              数据类型
src/store.tsx             校验、状态更新、localStorage、导出、重置
src/components.tsx        通用组件与检验趋势图
src/forms.tsx             新任务、复核、随访、说明与重置弹窗
src/pages.tsx             四个业务模块及患者详情
src/App.tsx               布局与路由
tests/workflows.spec.ts   浏览器业务测试
```

页面读取 `dataset.json`，不会写回该文件。复核意见、任务、联系记录和操作事件保存在当前浏览器的 `silver-guardian.demo.v1` 键中；更换浏览器、设备或站点端口不会自动同步。导出内容为这些交互记录及演示元数据，当前版本未实现导入恢复。

日期计算固定以 **2026-10-16** 为基准；新操作保留该演示日期及操作时刻（北京时间），不冒充真实业务发生时间。修改演示日期时同步检查档案、检验、出院、初始任务日期，并重置旧演示状态。

保存成功后才更新页面；浏览器拒绝存储时显示错误，保留表单内容。本地记录损坏时不静默覆盖，先提供原始内容导出与恢复入口。重置只移除本应用的键，不执行 `localStorage.clear()`。同源其他标签页的修改会通过 storage 事件同步；本版按单人演示设计，不提供多人并发冲突控制。

顶部身份为固定演示身份，不是登录系统。点击任务、预警、导出等操作均不通知患者或其他人员。

## 更换数据

字段以 `src/types.ts` 和已有 JSON 为准：

- `patients`：基本资料、共病、出院日期、管理人、模拟评分/分组、缺失信息、检验序列和诊疗时间线。
- `labs`：指标名称、单位、参考范围与观测值；与 `labDates` 一一对应。
- `tasks`：患者编号、任务名称、计划日期、负责人、状态及联系记录。
- 任务关联的患者编号必须存在，编号必须唯一，评分范围为 0–1。

修改文件后可通过「演示说明与数据来源」核对记录数量，并重置浏览器记录，避免旧状态与新数据混用。任何演示数据替换都应保留清楚的来源标记。真实风险结果接入前，需要先完成原模型的时间窗口、防泄露、校准及独立测试工作。

## 验证

```bash
npm run build
npm run test:e2e
```

Playwright 默认使用已安装的配套 Chromium。一般开发机器可先执行 `npx playwright install chromium`。本云环境已有系统 Chromium，可直接使用：

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

测试自动启动或复用 4173 端口的开发服务器，并使用独立浏览器上下文，不修改日常浏览器记录。覆盖统计、组合筛选、检验切换、复核与任务闭环、刷新持久化、未接通处理、重复任务控制、导出与隔离重置、存储失败、损坏记录、数据请求失败、未知页面和手机布局。

项目仍是本地交互原型；认证、多用户共享、真实模型推理及临床有效性验证属于后续工作。
