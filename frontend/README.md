# 银龄守护 · 医护工作台

使用真实历史数据的患者档案与随访管理前端。只读取你选择的患者宽表和再入院评分 CSV，不内置患者、模拟评分或预设随访任务，不运行 Python 模型。

## 启动

建议使用 Node.js 22 或 24。**在 `frontend` 目录执行**：

```powershell
npm ci
npm run dev
```

如果终端当前位于仓库根目录，先执行 `cd frontend`。更新仓库后重新运行 `npm ci`，以安装锁文件指定的依赖。

构建与预览：

```powershell
npm run build
npm run preview
```

## 打开真实数据

1. 在首页选择「患者健康画像宽表」和「再入院风险评分表」。
2. 点击「打开工作台」。页面按 `PATIENT_ID` 关联两份文件。
3. 支持 UTF-8、GB18030，单文件不超过 32 MiB。大型宽表可按患者抽取关联样本。
4. 查看工作台、患者档案、评分核对和随访任务。

文件仅在浏览器内存中读取，不上传服务器，不写进 GitHub。刷新后重新选择相同文件，可恢复按文件指纹隔离保存的核对与随访记录。没有导入文件时，不显示患者或统计数字。

## 数据口径

- 患者宽表要求 `PATIENT_ID` 唯一，并包含 `年龄`、`SEX`。慢病、画像、检验汇总和疾病评分按已有字段显示。
- 再入院评分表要求 `PATIENT_ID`、`入院时间`、`再入院风险评分`、`再入院30天实际`、`风险等级`。
- 完全相同的五列结果合并展示并保留出现次数；同患者同入院日期的不同结果逐条保留，不任意取平均或最高值。缺少就诊编号时不能确认事件身份。
- 年龄、性别、共病、画像、检验汇总与评分来自文件；姓名、出院日期、单位、检验日期或个体解释缺失时保持未提供。
- 页面保留历史模型输出，不将其视为已重新验证的个人事件概率。入院日期不能当成出院日期或模型计算时间。
- 核对和随访从空记录开始，仅保存用户当前填写的内容。未接通的任务保持进行中，可以安排下次处理日期。所有操作均不发送外部消息。

## 图表与评分参照

- 工作台的再入院评分直方图、等级占比和分位界限使用当前评分文件的全部原始行，包含重复行及未关联宽表的患者。图表统计单位是记录，不是患者；点击柱形可查看区间记录数。
- `models/readmission.py` 使用全量评分的第 33、66 百分位划分低、中、高风险。页面使用当前导出文件按相同分位数算法重算近似界限；导出只保留四位小数，界限同分不重新划级。当前文件可能只是样本，如原等级与重算界限不一致，页面会提示核对。
- 患者评分附 0–1 刻度、三组近似界限及本文件中的分位位置。“高于 X% 的评分记录”严格统计更低的评分，同分不计入；低风险只是相对分组，评分不能直接当作已验证的个人再入院概率。
- 历史评分图按真实入院日期绘点，纵轴固定 0–1。同日不同结果分别保留并断开连线，完全重复结果保留出现次数；不能将连线解释为连续监测或治疗效果。
- 检验范围图以各指标自身的历史最小、最大值为刻度，标记均值与末次值。没有日期、单位或正常参考区间时，不绘制检验时间曲线，也不判定异常。原始汇总数值可以展开查看。
- 共病评分按 0–1 绘制，并与当前宽表中同一疾病的有效样本中位数对照，缺失评分不按零处理。这是共病识别输出，样本中位数不是诊断界限，评分不代表未来发病概率。
- 画像归属度表示聚类归属把握，与再入院倾向和共病识别评分含义不同。

## 本地保存

原始 CSV 不写入 localStorage。核对意见与任务使用 `silver-guardian.history.v1.<文件指纹>` 保存，换文件不会串用记录。

顶部「导出记录」导出当前核对与随访记录，不包含原始医疗数据。侧栏「数据说明」可查看来源、导入时间以及清除当前文件的本地记录；清除前可导出备份，不影响其他文件或其他网站。

保存失败会保留表单并提示错误。本地记录损坏时暂停保存，保留原记录供导出和恢复。按单人使用设计，不提供多人并发冲突控制，也没有身份认证。

## 结构

```text
src/App.tsx                       真实数据导入首页
src/components.tsx                通用表单、弹窗与表格组件
src/files.ts                      记录导出
src/styles.css                    全局排版与响应式布局
src/history/data.ts               CSV 编码识别、校验、关联及差异统计
src/history/reference.ts          分位数、评分分布及同病中位数
src/history/charts.tsx             真实数据图表与评分解释
src/history/charts.css             图表与参照布局
src/history/HistoryWorkspace.tsx  档案、核对及随访工作流
src/history/history.css           业务页面样式
tests/history.spec.ts             业务与可读性检查
```

正文采用 16px，表格内容 15px，辅助文字和标签不低于 14px。手机端保持可读字号，宽表格在自己的容器内滚动。

## 验证

```powershell
npm run build
npm run format:check
npm run test:e2e
```

Playwright 需安装 Chromium（`npx playwright install chromium`）。本云环境可直接使用系统 Chromium：

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

测试中的小型数据仅用于自动化校验，不被产品加载。真实医疗文件与真实患者截图不提交到仓库。
